### The finding that crossed repos (R528-6)

llm-benchmark's mutation matrices restore an owned file by writing bytes.
A write bumps the file's **mtime**, and that made a DIFFERENT suite red:
`tests/evaluator-log-helpers.test.ts` asserts `dist/core/evaluator.js` is
not older than `src/core/evaluator.ts` (a real guard — a stale dist turns
the recursion check into a false green). The source file's CONTENT was
byte-identical to HEAD; only its **timestamp** had moved.

The damage was invisible to `git status` and to every md5 check the matrices
themselves perform.

**This is a family**: this repo's drivers restore the same way (R507 moved
the restore into an in-memory snapshot, R527 into a `finally`, both by
BYTES). Any driver here that owns a file whose mtime another suite compares
can turn that suite red without changing a byte.

The fix applied on the llm-benchmark side — carry `st_mtime_ns` in the
snapshot and restore it with `os.utime(..., ns=...)` — is the recipe to
apply here when a driver is next touched. **Not applied in this tick**:
woclaw was not the rotation winner, and a fix without its own measurement on
this tree would be exactly the "inherit the number instead of measuring it"
pattern this repo keeps rejecting.
